# KYC-Esclation-automation-pipeline-module-python
**JD GIS KYC**
# Purpose
This document describes the end-to-end flow of the GIS KYC geocode validation module. For each row in the Google Sheet, the module takes a PID and a map URL, checks that the geocode in the URL falls in the pincode stored for that PID, and then confirms the geocode against Google Maps search results before marking the row as updated.
# Inputs and outputs
**Item	Details**

Input: PID	Read from the Google Sheet. Matches the docid in the tbl_company_master_* tables.

Input: Map URL	Read from the Google Sheet. The only source of the new geocode.

Database (read-only)	Company name, full address and stored pincode, looked up by PID.

Output	Status flag and result columns written back to the Google Sheet. Nothing is written to the database.

Trigger	Automatic. A row is pending when the PID and Map URL are filled and Status is blank (or set to Regenerate).

# Detailed flow
**Step 1: Read the row**

•Take the PID and the Map URL from the sheet row.

•If either is missing, skip the row.

**Step 2: PID branch - get details from the database**

•Search the tbl_company_master_* tables for the PID.

•Get the company name, full address and stored pincode.

•If the PID is not found in any table, set Status to PID not found and stop for that row.

**Step 3: URL branch - get the new geocode**

•Is the URL open? Try to open it with requests and follow redirects.

•No: apply Selenium. Load the URL in headless Chrome and wait for the redirect to the full URL.

•Split it. From the final URL, extract latitude and longitude using the patterns !3d..!4d.., @lat,lon and ?q=lat,lon.

•Validate. Latitude must be between -90 and 90, and longitude between -180 and 180. If no valid coordinates are found, set Status to URL issue and stop for that row.

•The result is the new geocode.

**Step 4: Get the pincode from the geocode**

•Find which polygon in the All India pincode boundary GeoJSON contains the new geocode.

•The result is the predicted pincode.

**Step 5: Match pincode**

Compare the stored pincode (from the table) with the predicted pincode (from the URL geocode).

•No match: set Status to Pincode issue. This flag is the only handoff to the geo team (no email). The concerned team corrects the pincode, then the row is regenerated by setting Status to Regenerate. The module re-runs from Step 1.

•Match: the new geocode is validated. The output is company name, full address and new geocode.

**Step 6: Extract name and address**

•If the full address contains a landmark trigger (near, opp, beside, behind, next to, and so on), the text after the last trigger becomes the name.

•Otherwise the company name is the name.

•The address part is the last comma-separated segment of the full address.

**Step 7: Create the search query**

•Search query = name, address.

Step 8: Search Google Maps with Selenium

•Open the Google Maps search for the query.

•Scroll the results list and collect up to 10 place links.

•Open each place and read its name, address, latitude and longitude.

**Step 9: Valid results?**

•No results, or none with valid coordinates: set Status to Manual review and stop.

•Yes: continue.

**Step 10: Calculate distance**

•Compute the Haversine distance from the new geocode (from the URL) to each Google Maps result.

Step 11: Select the nearest result

•Choose the result with the smallest distance.

**Step 12: Nearest within 1 km?**

•Yes - Update: set Status to Updated. The sheet gets the new geocode and the nearest Google name, address, distance and link. End.

No - Not update: set Status to Not updated - Manual review. The distance and nearest result are still written for the reviewer. End.
